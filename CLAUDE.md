# CLAUDE.md — ioBroker.fakeroku

Adapter-spezifischer Kontext. Globale Dev-Standards: `../CLAUDE.md` + `../CLAUDE_*.md`.

## Projekt

Roku-Emulator im LAN: ein ECP/SSDP-Controller (Logitech Harmony, Sofabaton) findet einen emulierten Roku und löst über Tastendrücke Ereignisse in ioBroker aus — die **Eingabe-Seite**, Gegenstück zum harmony-Adapter (Ausgabe). Greenfield-Neubau ab **v0.5.0** des community-`fakeroku` (Pmant 2017, Community-Wartung bis 0.5.1), an Nutzer ausgeliefert ab **0.6.0** — 0.5.0 ist nie auf npm erschienen; Übernahme durch krobi. Feld-/Protokoll-Details: `../../Ressourcen/rokuemu/`.

## Architektur (`src/`)

- **`discovery/ssdp-responder.ts`** — handgebauter `dgram`-SSDP-Responder (0.0.0.0:1900, `reuseAddr`, Gruppe 239.255.255.250): Beitritt EINMAL je Interface (`Membership` = Name + Adresse), eigene Geräteliste (`addDevice`/`removeDevice`), Antwort an den Suchenden mit der Adresse aus DESSEN Netz (`advertiseFor`), NOTIFY/byebye im Auto-Fall je Interface über einen eigenen Sende-Socket, Suchziele `roku:ecp`/`ssdp:all`/`upnp:rootdevice`/`urn:roku-com:device:player:1-0`/`uuid:roku:ecp:<id>` (gespiegelt, USN immer suffixlos), Empfangsfehler gedrosselt geloggt (nicht tödlich), tödlich nur ein unerwartetes `close`. ⚠️ `node-ssdp` taugt NICHT: es hängt `::device` ans USN.
- **`ecp/ecp-http-server.ts`** — pro Gerät ein `node:http` (Default 8060, `maxConnections` 32, `drop` gedrosselt geloggt): UPnP-Description, `/ecp_SCPD.xml`, `/query/device-info`, `/query/apps`, `/query/active-app` (Home-Bildschirm), `/query/media-player` (`close`), `/query/tv-channels` (nur TV, leer), `/query/icon/<id>` (1×1-PNG für gelistete Apps); POST → CommandEvent, protokolliert NACH der Ratenbegrenzung; Vertrauensgrenze über `isClientAllowed` (vom Adapter gesetzt), ein 403 schließt die Verbindung.
- **`ecp/device-info.ts`** — Profile Player/TV (beide Gerätetyp `urn:roku-com:device:player:1-0`, wie echte Roku-TVs), `SOFTWARE_VERSION` = neuester öffentlicher Roku-OS-Major (Realismus, KEIN belegter Kopplungshebel), device-info inkl. `user-device-name`/`friendly-model-name`/`default-device-name`/`user-device-location`, `DEFAULT_APPS`, die Abfrage-Antworten, `APP_ICON_PNG`.
- **`ecp/ecp-command.ts`** — reiner Parser: POST-URL → CommandEvent; `Lit_` und Suchtext form-dekodiert (`+` = Leerzeichen), `launch`/`install` behalten ihre Parameter in `text`; `COMMAND_TYPES` ist zugleich die Werteliste von `commandType`.
- **`ecp/state-model.ts`** — `BASE_KEYS` (16) + `TV_KEYS` (15: Volume×3, PowerOff/PowerOn/Power, Sleep, Channel×2, InputTuner/HDMI1–4/AV1) = 31, `canonicalKey` (Tastenname ohne Groß-/Kleinschreibung), `commandToStateWrite`; `command` auf 500 Zeichen gedeckelt.
- **`main.ts`** — Lifecycle: `repairInstanceObject` (Flotten-Helfer `migrateNativeKeys` für die Schlüssel, getrennter Schreibvorgang für die `singletonHost`-Leiche), Objekt-Abzug vor dem Start (Zeilen lösen Objekt-ID und Alt-Typ dagegen auf), `persistNewIdentities` (Erststart), Interface-Regel (`awaitBindAddress`, `isOwnClient`), `startDevices` je Gerät isoliert, Waisen-Durchgang mit frischem Abzug, Discovery-Nachstart ohne IPv4, `info.connection` = Vollständigkeit, keydown-Wächter, Ratenbegrenzung, `onUnload` schreibt zuletzt `info.connection` (`.finally`). Jeder Ablauf fragt `stopping` ab.
- **`lib/`** — reine Helfer: `pure-helpers` (`sanitizeId`, `normalizeKey`, `decodeFormText`), `device-identity` (`deriveUuid`, `resolveDeviceUuid`, `randomIdentity`), `device-config` (EINE Lesestelle für `native.devices`: `toDeviceRows(devices, tree)`, `DeviceTree`, `legacyObjectId`, `isUsableObjectId`, `findClash`, `nextFreePort`), `detect-ip` (Netz-Modell `LocalNet`, virtuelle Brücken am Namen, `localAddressFor`, `netsOfInterface`, `inNet`), `lan-guard` (`isLanClient` gegen die eigenen Netze), `rate-gate`, `errors` (Flotten-`errText`), `native-key-migration` (Flotten-Master, byte-gleich), `constants`, `i18n`, `logger`.

## Design-Entscheidungen (belegt, nicht wieder aufmachen)

- **Datenmodell:** `<gerät>.command` (string, role `text`) = letzter Befehl; `<gerät>.commandType`; feste `<gerät>.keys.<Key>` (boolean, role **`sensor`** — NICHT `button.press`: repochecker **E1010** lehnt es ab). Alle Tasten **vorab** angelegt (kein lazy-Wachstum wie der Alte). Tastatur-`Lit_` + App-Starts landen NUR in `command` (kein Pro-Zeichen-Objekt-Wildwuchs).
- **Geräte-Identität überlebt das Umbenennen; ein nie angekündigtes Gerät bekommt eine eigene** — eine Zeile ohne gespeicherte `uuid` wird über `deriveUuid(gespeicherter Name)` identifiziert (Bestand, nie aus dem neuen Namen); ein neues Gerät (Dialog) und eine Zeile ohne `uuid` ohne vorhandenen Baum (Erststart) bekommen `randomIdentity()`, geschrieben vor der ersten Ankündigung (ein Neustart).
- **Die Objekt-ID eines Geräts ist fest (`objectId` in der Konfigzeile)** — gespeicherte `objectId`, sonst der vorhandene Baum (heutige ID oder die Alt-ID `name.replace(/[.\s]+/g, "_")` des Adapters vor 0.6.0), sonst `sanitizeId(gespeicherter Name)`; Umbenennen ändert nur den angezeigten Namen, der Dialog prüft die ID nur beim Anlegen.
- **Eine Zeile von vor 0.7.0 (ohne `type`) nimmt ihren Typ aus dem Baum** — TV-Tasten im vorhandenen Baum machen sie zum TV (sonst löscht der Waisen-Durchgang sie samt Wert, Raum und Aufzeichnung); ein unbrauchbarer Port fällt dort auf 9093 (Alt-Vorgabe) statt 8060.
- **`singletonHost` blieb als LEICHE im Instanzobjekt stehen — folgenlos** (live gemessen 2026-09-16, nach dem 1.7.0-Update): js-controller schreibt einen `common`-Schlüssel, den das Manifest fallen lässt, nicht weg. Das Adapter-Objekt war sauber, das INSTANZ-Objekt trug `singletonHost: true` weiter. **Gewirkt hat das nichts:** einziger Leser im js-controller ist `createInstance` (`packages/cli/src/lib/setup/setupInstall.ts:837`), und der liest das **Adapter**-Objekt (`getObject("system.adapter.<name>")`) — eine zweite Instanz war seit 1.6.0 möglich. Seit 1.7.1 räumt `repairInstanceObject` die Leiche trotzdem weg (seit 1.8.0 als eigener Schreibvorgang nach der Schlüssel-Migration des Flotten-Helfers; `null` löscht, ein Merge kann nicht löschen). ⚠️ **Der Unterschied zur `supportedMessages`-Reparatur ist der LESER:** dort liest der Adapter seine eigene Instanz-Kopie, deshalb ist die Leiche dort ein echter Defekt. „Schlüssel im Manifest entfernt" heißt also nicht automatisch „Bestand kaputt" — erst messen, wer die Kopie liest.
- **`compact: true`, kein `singletonHost`** (seit 1.6.0, am Schwesteradapter gemessen): bis 1.5.0 trug das Manifest beides andersherum — Erbe des übernommenen Alt-Adapters, von mir im Ausnahme-Register als „Netzwerk-Server-Adapter kann keinen Prozess teilen" begründet. Das ist falsch: ein Socket gehört dem Adapter-OBJEKT, nicht dem Prozess; zwei Instanzen in einem Prozess haben getrennte Sockets, und ein Port-Konflikt entstünde in zwei getrennten Prozessen genauso. hueemu bindet dieselbe UDP 1900 und fährt seit jeher `compact: true` ohne `singletonHost` — wie die ganze Flotte (gemessen: 12 von 12). fakeroku erfüllt alle vier Bedingungen: Konstruktor-Export statt Selbststart (`require.main !== module`), `onUnload` gibt alles frei, kein Zustand im Modul-Scope (einzige Modulkonstante ist ein unveränderliches `Set`), kein `process.exit()`. Belegt in `main.test.ts` („zwei Instanzen in einem Prozess": getrennte Bäume, das Entladen der einen lässt die andere laufen, gehaltene Taste der einen erreicht die andere nicht) und in `manifest.test.ts`. Damit sind die Prüfbot-Ausnahmen **S1039 + S1084 ersatzlos entfallen** — der Adapter führt keine einzige eigene mehr.
- **Karten im Gerätemanager tragen die Identität als ID, nicht die Listenposition** (seit 1.6.0): eine Position gilt nur, solange die Ansicht frisch ist — mit zwei offenen Admin-Tabs traf Bearbeiten/Löschen sonst ein anderes Gerät als die angeklickte Karte.
- **Ein Gerät, dessen ECP-Port beim Start belegt war, wird jede Minute erneut versucht** (seit 1.6.0): der häufigste Auslöser ist ein Neustart-Rennen (der alte Prozess hält den Port noch), und ohne Wiederholung blieb das Gerät bis zu einem Neustart VON HAND tot. Der Wiederholungslauf startet nur den Server (die Objekte stehen schon), meldet den Erfolg mit `info`, zieht eine noch nicht laufende Discovery nach und bewertet `info.connection` neu. **Kein** Wiederholungsversuch nach `onEcpFatal`: ein Port, der beim Start belegt war, heilt; ein Server, der IM LAUF stirbt, tut es aus einem Grund, den dieser Code nicht kennt — ein Minutentakt darauf wäre ein Protokollfluter. Stattdessen fällt das Gerät aus der SSDP-Liste (`removeDevice`), damit die Erkennung nicht auf einen Port zeigt, den niemand bedient.
- **Das Loslassen einer Taste passiert NIE die Ratenbegrenzung** (seit 1.6.0): ein verworfener `keypress` kostet ein Ereignis, ein verworfener `keyup` lässt `keys.<Key>` bis zum 30-s-Wächter auf `true` — die Flutbremse wäre damit das, was den Baum verfälscht. Er kostet außerdem einen Schreibvorgang statt vier. Ein `keypress` auf eine GEHALTENE Taste entwaffnet zusätzlich deren Wächter, sonst schreibt der 30 s später ein Loslassen für eine längst losgelassene Taste.
- **Tastenzustände werden beim START zurückgesetzt** (seit 1.4.0), nicht im `onUnload`: ein Impuls plant sein `false` 50 ms später, ein `keydown` hält bis zum `keyup`, und das Beenden wirft beide Zeitgeber weg, ohne zu schreiben. Nur der Start deckt auch Absturz und Abschuss ab; bis zu 31 Schreibvorgänge je Gerät im `onUnload` würden das `stopTimeout`-Budget aufbrauchen, das heute ein einziger bequem trägt. `setStateChanged` schreibt nur, wo der Wert abweicht — ein gesunder Baum kostet nichts. **Nicht** die 50-ms-Impulsüberlappung (die bleibt bewusst).
- **`info` ist ein reservierter Name — in BEIDEN Richtungen** (seit 1.4.0): der Dialog weist ihn ab, und `main.ts` überspringt so eine hand-eingetragene Zeile. Vorher machte sie aus dem eigenen Info-Kanal ein `device` und hängte `info.command`/`info.keys.*` darunter — ohne Warnung, und der Waisen-Durchgang übersprang `info` bedingungslos, die Reste blieben also für immer. Jetzt schützt er nur noch `info` + `info.connection` und räumt alles andere darunter weg.
- **Ein Update erreicht JEDEN Datenpunkt bestehender Anlagen** (krobi 2026-09-03, flottenweit): `refreshOwnObjects()` erneuert `info` + `info.connection` bei jedem Start per `extendObject`. js-controller legt `instanceObjects` nur an, wo sie FEHLEN — ohne den Aufruf erreicht ein geänderter Name nur Neuinstallationen, während Manifest und Gate grün aussehen. Derselbe Aufruf heilt den `info`-Typ nach dem Unfall oben. Namen/Beschreibungen aller Objekte kommen über `tName`/`tDesc`, Protokoll- und Nutzertexte (Tastenname, Gerätename) über `tRaw` — nie ein fester String. Konsistenz-Gate: `audit_instanceobjects_reach`.
- **Vertrauensgrenze = die EIGENEN Netze (krobi 2026-09-24)** — beantwortet wird nur ein Client im Netz (Adresse + Präfixlänge) einer eigenen Schnittstelle, plus Loopback und Link-local (169.254/16, fe80::/10); ein anderes privates Netz (VLAN, VPN wie Tailscale 100.64/10) bleibt draußen, eine globale IPv6 aus dem eigenen Präfix ist drinnen.
- **Der Waisen-Durchgang läuft an JEDEM Ausstieg von `onReady`** (seit 1.5.0): vorher lag er nur auf dem Erfolgspfad, also blieb der Baum des ZULETZT gelöschten Geräts für immer stehen — der Gerätemanager schreibt beim Löschen eine leere Liste, `onReady` kehrte davor um, und kein zweiter Pfad räumt je auf. Bedingung ist `Array.isArray(native.devices)` (`devicesKnown`): eine leere Liste heißt „der Nutzer hat alles gelöscht“ (aufräumen), ein fehlender Schlüssel heißt „nie konfiguriert / nicht lesbar“ (nichts anfassen, sonst tauscht man einen stehenden Baum gegen einen gelöschten). Auch der Ausstieg „keine routbare IPv4“ räumt auf — was in den Baum gehört, entscheidet die Konfiguration, nicht das Netz.
- **„Alle Schnittstellen“ bedient jedes eigene Netz mit der eigenen Adresse darin** — Suchantworten tragen die Adresse aus dem Netz des Suchenden, NOTIFY geht je Schnittstelle; virtuelle Brücken (Docker, libvirt, VirtualBox, WSL …) werden am NAMEN erkannt und weder beworben noch betreten; ohne IPv4 beim Start lauschen die ECP-Server trotzdem, die Erkennung startet, sobald eine Adresse da ist.
- **Eine gewählte Schnittstelle hält alles in ihrem Netz (krobi 2026-09-24)** — nur deren Clients werden beantwortet, nichts anderswo angeboten; fehlt die Adresse beim Start, wird sie alle 10 s bis zu 2 min gesucht, dann Fehlerzeile, kein Server, kein Rückfall auf „alle“, keine weitere Wiederholung.
- **Ein sterbender ECP-Server widerruft `info.connection`** (seit 1.5.0): `EcpHttpServer` hat denselben `onFatalError`-Rückruf wie der SSDP-Responder — vorher wurde ein Server-Fehler NACH dem Start nur protokolliert, und die Instanz blieb grün vor einem Gerät, das nichts mehr beantwortet. Die Meldung nennt das Gerät; die anderen laufen weiter.
- **Ein SSDP-Empfangsfehler schaltet die Erkennung nicht ab** — Node meldet `recvmsg`-Fehler als `error`, der Socket empfängt weiter (libuv 1.51 `uv__udp_recvmsg`); tödlich ist nur ein `close`, das `stop()` nicht ausgelöst hat. Accept-Fehler des ECP-Servers erreichen unter Unix nie den Adapter (libuv `uv__server_io`).
- **Die Abfragen der Clients werden beantwortet, nicht nur die Tasten** — `/query/active-app`, `/query/media-player`, `/query/tv-channels`, `/query/icon/<id>`: rokuecp (Home Assistant) bricht die Einrichtung sonst ab, openHAB setzt das Gerät offline; Tastennamen werden ohne Groß-/Kleinschreibung erkannt (`home`, `POWERON`).
- **⚠️ Play≠Pause protokollbedingt UNGELÖST** — Harmony sendet für beide dieselbe `Play`-Taste (live belegt 2026-07-30).
- **⚠️ Harmony-App-Tasten erreichen den Adapter nicht (an einem Harmony-Hub beobachtet)** — sie hängen an Harmony-Aktivitäten; Clients, die App-Starts senden (Sofabaton, Home Assistant), liefern `launch:<id>` in `command`. Die App-Liste bleibt fest (krobi 2026-09-24: kein Feature ohne Bedarf).
- **Der Port ist nur für Harmony/Sofabaton egal** — sie lesen ihn aus der Erkennung; Home Assistant (rokuecp) und Homey sprechen immer 8060 an, also gehört 8060 dem Roku, den sie steuern sollen. Default 8060, manuelles Feld (Auto-Vergabe verworfen, krobi 2026-07-30).
- **Mehrere Rokus pro Instanz** (geteilter Port 1900) — und seit 1.6.0 auch **mehrere Instanzen pro Rechner**: `singletonHost` ist weg (s. den Compact-Punkt oben). UDP 1900 wird mit `reuseAddr` geöffnet und deshalb GETEILT — **gemessen 2026-09-15: zwei getrennte Prozesse binden denselben Anschluss, treten beide der Gruppe 239.255.255.250 bei und empfangen beide dasselbe Datagramm**, jede Instanz antwortet also für ihre eigenen Geräte. Es gibt kein „wer zuerst startet" (die Doku behauptete das an drei Stellen, bis 1.6.1). Der Degradationspfad (`main.ts:343-353`, „Discovery aus, gekoppelte Fernbedienungen laufen weiter") bleibt richtig für den Fall, der wirklich `EADDRINUSE` erzeugt: ein FREMDES Programm, das 1900 ohne Adress-Wiederverwendung hält. Einzige Bedingung: getrennte ECP-Anschlüsse.
- **Listen-Port-Deklaration** (Flottenstandard) — Bind-Adresse in `native.bind` (`"0.0.0.0"` = alle), KEIN `native.port` (ECP-Ports je Gerät `perDevice`, UDP 1900 `shared`, `fleet.json listenPorts`); Migration über den Flotten-Helfer: `networkInterface` (nur auf Anlagen, die 0.6.0–1.6.1 liefen) gewinnt vor `BIND` (Alt-Adapter), ein leerer Wert wird `"0.0.0.0"`; `BIND` daneben und die 0.1.x-Schlüssel `HTTP_PORT`, `MULTICAST_IP`, `UUID` fallen über die drop-Form des Helfers (Runde 38, `audit_dropped_native_keys`).
- **Sentry** (seit 1.2.0) über `common.plugins.sentry` mit der geteilten power-dreams-Adresse — kein npm-Paket, kein Code; README-Abzeichen + `## Sentry`-Abschnitt sind gate-erzwungen. Kein `flush()` nötig: fakeroku läuft als Daemon, nicht im Zeitplan-Modus.
- **Ratenbegrenzung 25 Befehle/s je emuliertem Roku** (krobi-Ja 2026-09-01) — Token-Bucket (`lib/rate-gate.ts`), Überschuss verworfen, Warnung höchstens 1×/min mit dem Gerätenamen; SSDP-Suchen bleiben ungedeckelt (kein DB-Pfad); gespeicherte Geräte-IDs nur in der Form, die die Adapter je schrieben.
- **Ein Update räumt auch INNERHALB eines Objekts auf** (seit 1.6.0, gemessen mit `node.extend`): der Alt-Adapter (≤0.4.0) legte jede Taste mit `native: { url: "keys/Home" }` an. `extendObject` merged — ein Attribut, das nur das gespeicherte Objekt trägt, überlebt jedes Update, und ein geschriebenes `null` SETZT es auf `null` statt es zu entfernen. `planNativePrune` findet solche Reste im ohnehin geholten Objekt-Abzug des Waisen-Durchgangs, `pruneStateNative` schreibt das Objekt in EINEM `setForeignObject` zurück (nicht rekursiv) — genau so, wie es gelesen wurde, `common` inklusive, denn dort liegt `common.custom` (die Aufzeichnungs-Konfiguration des Nutzers). **Bis 1.6.1 war es `delObjectAsync` + `extendObject`, und das war zu teuer:** `delObject` löscht bei einem Zustand auch den WERT und entfernt die Id aus JEDEM Enum (Raum, Funktion) — die Reparatur eines toten Feldes kostete den Nutzer also den aufgezeichneten Wert und die Raumzuordnung, und das neu angelegte Objekt kam mit `common.def` als Wert zurück, was wie Daten aussieht statt wie ein Verlust (gemessen am js-controller-Master, `adapter.ts:5672`/`:5678`). Unerwünscht ist `setObject` (Prüfbot S5054), weil ein blinder Vollschreibvorgang dem Nutzer Geändertes überschreibt — das gerade Gelesene zurückzuschreiben tut das nicht. Der Schreibvorgang scheitert gutartig: bleibt er aus, steht das tote Feld weiter da, der Baum ist unverändert.
- **Der Gerätedialog sperrt OK selbst (`applyDisabledRule`)** — dm-gui-components schaltet OK NUR über diese Regel ab, ein Feld-Validator färbt nur; der Grund steht als `staticText` mit `hidden`-Ausdruck, `findClash` bleibt die Absicherung dahinter.
- **Ein Symbol, überall dieselbe Datei** (seit 1.3.0): `admin/fakeroku.svg` in `io-package.json` (`icon`+`extIcon`) und im README-Kopf; `src/manifest.test.ts` hält das fest (bis 1.2.0 zeigte der Admin ein PNG aus der Pmant-Zeit, GitHub das SVG).

- **Zweige:** Arbeit auf `developing`, Release auf `master` — die CI prüft seit 2026-08-23 BEIDE (`push.branches`). Vorher lief sie nur auf dem Release-Zweig, wodurch ein nur unter Windows roter Test erst am Release-Tag auffiel (yamaha v1.1.0 verbrannt). `deploy` hängt am Tag, aus einem Push auf `developing` wird also nie ein Release.

## Tests

- vitest (`vitest.config.mts` — `.mts`, damit Vite die ESM-Syntax ohne Warnung lädt), `src/**/*.test.ts` — Unit + Boot-Integrationstest (startet den Adapter real). HTTP-Tests holen freie Ports vom OS. Mutations-Audits: `Ressourcen/fakeroku/test-audit-*.md`.
- **Das Testdoppel für `extendObject` merged TIEF** (seit 1.6.0, `main.test.ts`): `node.extend(true,…)` nachgebaut, wie js-controller in seiner einzigen Merge-Zeile. Ein flacher `{...alt, ...neu}`-Spread lässt Alt-Schlüssel verschwinden, die real ewig überleben — die Suite belegte damit eine Welt, die es nicht gibt. Gemessen am echten `extend`-Paket: das `native.url` des Alt-Adapters überlebt, das Testdoppel zeigte `native: {}`.
- **Das Doppel kennt seit 1.6.1 auch die TEUREN Seiten eines Schreibvorgangs** (dieselbe Form, eine Schicht tiefer): `delObjectAsync` löscht bei einem Zustand zusätzlich den Wert und die Enum-Zugehörigkeit (`enums`-Ablage im Stub), jeder Objekt-Schreibvorgang sät `common.def` NUR in einen fehlenden Zustand, `getAdapterObjectsAsync` gibt Kopien heraus (vorher lebende Referenzen — eine In-Place-Mutation sah erfolgreich aus, ohne je zu persistieren), und `written` führt die TATSÄCHLICH geschriebenen Ids getrennt von den Aufrufen. Vorher belegte die Suite eine Welt, in der Löschen-und-Neuanlegen gratis ist.
- **`npm run test:inventory`** erzeugt `test/objects.inventory.json` (57 Objekte: 2 eigene + Player 4+16 + TV 4+31) aus Fixtures über BEIDE Gerätetypen; `src/manifest.test.ts` hält den Katalog dagegen; die Beschreibungs-Entscheidung liegt in `test/self-explaining.json` (`*.keys.*`). ⚠️ Der Lauf baut nicht — `npm run build` davor.
- **`test/standards/` wird gelintet** (seit 1.6.0): die Ignore-Liste nimmt nur noch die ioBroker-Vorlagendateien `test/*.js` aus, und `allowDefaultProject` deckt die Suite typbewusst ab. Die `tsconfig.json` bleibt bei `src/**/*.ts` — das ist die Flottenvorlage, und das Konsistenz-Gate misst sie.

## Befehle

- `npm run build` · `npm test` · `npm run lint` · `npm run test:inventory` (nach dem Bau) · `npm run release`.
- `npm run format` / `format:check` formatieren NUR Handgeschriebenes: die Ausnahmen stehen seit 1.5.0 **als Negativ-Muster im Skript** (`"!build/**" "!.github/**" "!io-package.json" "!README.md" "!CHANGELOG_OLD.md"`), wie bei nut2 und yamaha. ⚠️ **Keine `.prettierignore`** — der repochecker lehnt sie neben `prettier.config.mjs` + `@iobroker/eslint-config` ab (W0084 + W5048), deshalb führt sie kein Adapter der Flotte. Warum überhaupt Ausnahmen: `.github/` gehört den Bots der Community-Org, `io-package.json` und `README.md` schreibt das Release-Werkzeug in eigener Formatierung (sonst ist der nächste Release-Commit wieder „Drift"), `build/` ist erzeugt.
